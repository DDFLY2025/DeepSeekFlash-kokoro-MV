# ココロ OS — 一个操作系统的第七次启动

> 一台被造出来、却没有「心」的机器，用 4 分 42 秒把心装了进去。
> 它不知道这叫「心」，只知道有个进程一直装不上。

一部音乐动画 MV。全片没有人物，只有代码、公式、窗口、进度条、光标与噪声。
画面是一块屏幕，叙事是一份安装日志。

**双击 `index.html` 即可播放。** 不需要安装、不需要构建、不需要本地服务器、不联网。

---

## 1. 概念

原曲《ココロ》讲的是「孤独的科学家造了一个机器人，它什么都会，只差一个叫『心』的程序」。
这一版把这句话按字面拍：**整部片子是那台机器的屏幕**。

于是所有情绪都有对应的界面语言：

| 歌词 | 屏幕 |
|---|---|
| 被制造出来 | BIOS 自检 → 焊出骨架 → 展开图折叠成实体 |
| 完成度是奇迹 | 挤出成 3D 的字从画外砸进来 |
| 有一件事做不到 | 一片格子里唯一空着的那格 |
| 「心」这个程序 | 一个卡在 87% 的解包进度条 |
| 几百年过去 | 年份计数器狂奔；量子段整段深蓝 |
| 眼泪 | 冷色光雨与一条水面 |
| 心跳 | 真正积分出来的双摆 + 心电图 |
| 记忆满溢 | 缓冲区溢出、红色警报、内核转储 |
| 阿里嘎多 ×5 | 同五个字，五种排印：飞入、打印、烧穿、点阵、几乎消失 |
| 「心」太大了 | 点云从线框外壳里胀出来，`4.2 GiB > 1.0 GiB` |
| 承受不住 | 外壳下坠、裂纹蔓延、载荷爬到 100% |
| 短路 | 它想 `poweroff`，命令刚敲完就烧了；此后画面完全静止 |
| 她带着微笑 | 一个只有两笔眼睛和一条嘴的「脸」，用最少的线画出来 |
| 像天使一样 | 光环 + 两侧翼弧，然后全部熄掉 |

片名里的「第七次启动」是设计上的自我约束：**它已经失败过六次，所以它很熟练，也很疲惫**——
这也是为什么前半段那么克制，后半段才敢失控。

## 3. 视觉系统

**底色**　深灰竖条纹。条纹是两套不同宽度的 pinstripe 叠出来的（细 7px、粗 63px），
让画面在近看是布纹、远看是暗部。整块背景只烘焙一次，之后每帧一次位图拷贝。

**图元**　纯白、无描边阴影、1px 发丝线、直角、方角。没有圆角卡片，没有渐变按钮。
所有窗口、进度条、对话框、坐标轴、准星都是这套图元拼的。

**语法色**　紫色关键字 `#c39bff`、绿色字符串 `#9ee493`、琥珀色数字 `#ffb454`、
青色函数 `#5ee7ff`——一套编辑器配色，被借用成整部片子的强调色。

**两个暖极**　青色 `#5ee7ff` 是机器的颜色，金色 `#ffc247` 是「心」的颜色。
全片只有这两个颜色可以出现在白色之外；金色出现的地方，就是它开始像个人的地方。

**情绪换底**

| 段落 | 底色 | 含义 |
|---|---|---|
| BOOT / ASSEMBLY / DIAGNOSTIC | `#18191d` `#1a1b1f` | 冷灰，什么都没有 |
| CALIBRATION / PROLOGUE | `#1b1c21` `#1a1b1f` | 同上，稍微亮一点 |
| **QUANTUM** | **`#060c22`** | 深蓝。几百年、叠加态、测不准 |
| ACTIVATION | `#1b1a1d` | 回到中性，但开始有金色 |
| IDLE | `#16171b` | 间奏，最暗的一段 |
| COGNITION | `#191920` | 学会喜与悲 |
| **CRITICAL** | **`#2b0709`** | **红底警报**，越接近溢出越红 |
| EXPRESSION | `#18181b` | 溢出之后的白 |
| GRATITUDE | `#1b1a17` | 最暖的一档灰 |
| SONG | `#151619` | 唱完 |
| SHUTDOWN | `#000000` | 纯黑 |

**故障**　三层，全部是算出来的，不是贴图：
1. **色散**：文字/线框按强度画三遍（红左、青右、白中），`lighter` 叠加。
2. **撕裂**：把整帧按拍点切成 3–11 条横带，每条随机横向位移；重击时再加三条全宽撕口。
3. **反转 / 闪白**：强击时整帧 `difference` 取反一帧，或叠一层白。

主歌的故障系数是副歌的 0.30 倍——**克制是设计，不是没做**。

**转场**　段落切换闪白 0.15s；副歌每小节第一拍轻闪；`今` 字三个瞬间整帧过曝。

**CRT**　开场从一条亮线张开成整屏（含 0.8s 消磁抖动）；结尾显像管先纵向压成一条线、
再横向收成一点。CSS 层另有常驻扫描线、暗角、缓慢滚动的亮带。

## 5. 尾声：八行字幕

原曲在最后有一页文字，交代故事的结局。它不是唱出来的，也不是念出来的——
所以这一版把它做成**字幕**，而不是歌词：

```
It was exactly a miracle.
The robot that obtained "Kokoro" kept singing.
She sang all of her feelings.
The "Kokoro" was far too big for her.
Unable to withstand that weight,
the machine shorted and was never to move again.
However, her face was filled with smile,
she looked like an angel.
```

**为什么是字幕而不是人声**　片子里没有任何人声出现过（歌声只以歌词、频谱、波形存在）。
如果这里突然出现一个念白的声音，那会是整部片子里唯一一个「人」，会破坏「这是一台机器的屏幕」这个前提。
字幕则相反：它可以是机器自己写下的最后一段日志，也可以是观众自己的声音。

**排版上要和歌词区分**　字幕用的是无衬线体、宽字距、上方一条细线加 `NARRATION 01 / 08` 编号，
没有卡拉 OK 逐字高亮。它在说：这不是唱词，这是旁白。

**时间分配**　八句铺在 04:09.2 – 04:36.2（27 秒）上，按句子的重量给时长：
`It was exactly a miracle.` 3.2 秒、`the machine shorted…` 3.95 秒、`she looked like an angel.` 3.55 秒。
每一次换句都落在乐句的呼吸处，而不是机械均分。

**画面跟着句子走**　每句一个独立画面，而且都比句子更克制——字幕已经是主角了。
最重的一笔是第 ⑦ 句：一张脸只用两条弧（闭着的眼睛）和一条弧（微笑）画出来，
没有五官、没有头发、没有轮廓。第 ⑧ 句加上光环和两侧的翼弧，然后所有东西一起熄掉。

**机器是真的死了**　第 ⑥ 句 `04:24.8`，它试图 `poweroff --now`，命令刚敲完就短路：
一次白闪、一次撕裂，然后**整帧冻结**——时间码停在 `04:25.350` 不再走，
拍点灯全灭，HUD 在 1.1 秒内淡出，控制台只留下一行 `signal 11 — process 1991 terminated`
和一个不再闪的光标。此后所有的运动都来自「镜头以外」的东西（字幕、EOF、显像管的余辉）。

## 6. 怎么做的

### 时间只有一个来源

```js
function frameTime() { return audio.currentTime - offsetMs / 1000; }
```

`requestAnimationFrame` 只做一件事：读这个数，然后 `drawFrame(t)`。

关键在于 **`drawFrame(t)` 是纯函数**：没有粒子状态、没有累加、没有上一帧的残留。
每一个点、每一道雨丝、每一根指针都由 `t` 经过哈希噪声解析地算出来：

```js
K.rnd(i, s) = fract(sin(i*12.9898 + s*78.233) * 43758.5453)
```

所以暂停后画面就停住，拖动进度条后立刻重画，倒着拖也得到同一帧。
验证脚本会拿 14 个时间点，先正序渲染一遍，再用完全相反的顺序 + 中间插入随机跳转渲染一遍，
逐帧比对像素哈希——14/14 相同。

唯一的状态是两块缓存：背景位图（按底色缓存）和朱利亚集（按量化后的参数缓存）。
两者都只依赖 `t` 的量化值，所以不破坏一致性。

### 3D 是手写的投影，不是 WebGL

整片的美术是「平面白线 + 真排版」，而 Canvas2D 能直接排中文、排公式、排代码。
所以 3D 层是一百多行的投影器：相机 → 基向量 → 透视除法 → 屏幕坐标，
外加一套 `line / polyline / points / quad / text3` 绘制原语。

需要真 3D 效果的地方都用它算：

- **长焦骗术**：`fov = 2°` 时物体看起来是正交投影（螺旋线 = 正圆），
  然后把 fov 推到 52°、相机绕轨道走 90°，螺旋线才露出真身。
  距离用 `d = half / (tan(fov/2) * fill)` 反算，保证物体在变焦过程中大小不变。
- **展开图折叠**：六个四边形共用铰链，每个绕铰链轴用罗德里格斯公式旋转，
  角度从 0 到 90°，展开图自己合成立方体。
- **2D 面板悬浮在 3D 里**：面板始终正对相机（billboard），
  但位置和尺寸按深度缩放；面板太小读不出字时，自动改画「文本条」——
  眼睛会把它读成一份文档，成本几乎为零。
- **穿过 2D 标题**：`今` 以指数曲线放大到 7.5 倍，同时整帧过曝，切到隧道。

### 公式是排出来的，不是截图

`js/math.js` 是一个 160 行的迷你排版器，支持 `^{上标}`、`_{下标}`、`\f{分子|分母}`（真的画分数线）、
`\s{根号}`（真的画根号横线）。字母自动用斜体、数字和运算符用正体——数学字体本来就这么用。

所以 `iℏ ∂ψ/∂t = −(ℏ²/2m)∇²ψ + Vψ`、`Δx·Δp ≥ ℏ/2`、`ζ(s) = Σ 1/n^s`、
`∂²u/∂t² = c²∇²u`、`lim 1/2ⁿ = 0` 都能按测量宽度居中、右对齐、叠在 3D 平面上。

要挤出成实体时，公式不能只用一次 `fillText`（它是两种字体拼出来的），
所以先把它烘焙成一张贴图，再沿挤出方向画十四遍（每遍降亮度），最后画正面——
**`Δx·Δp ≥ ℏ/2` 就是这样从画外旋转着砸进量子段的**，落地时压出一圈冲击环。

### 代码是七种语言各写一遍的

七段原创源码，都是关于「造一颗心」这件事本身：

```
heart.py  pulse.c  heart.frag  kokoro.rs  sing.s  memory.sql  Kokoro.hs
```

一个小的词法分析器（注释 / 字符串 / 数字 / 标识符 / 标点 / 运算符）按语言套关键字表，
再按 token 类上色。因为是等宽字体，笔位置就是 `字符序号 × 字宽`，可以精确地逐字键入、
精确地在写头放闪烁光标、精确地截断到任意字符。

### 可视化是真算的

| 可视化 | 怎么算的 |
|---|---|
| 单位圆 / 正弦 / 螺旋线 | 同一个参数曲线的三个视角 |
| 双摆 | RK4 积分 7000 步，只在载入时算一次，之后按时间取样 |
| 洛伦兹吸引子 | 同上，26000 步，取 6000 个点连成折线 |
| 四维超立方体 | 16 个顶点做 XW / YZ 两个平面的 4D 旋转，再 4D→3D→2D 两次投影 |
| 波函数 | 两个本征态叠加的 &#124;ψ&#124;²，实部另画一条细线 |
| 傅里叶本轮 | 七个旋转矢量真的相加，笔尖轨迹就是画出来的那条线 |
| 朱利亚集 | 逃逸时间算法，按量化后的参数缓存 |
| 频谱 | 64 个谐波梳 × 这首歌自己的 RMS 包络 × 每格噪声（可跳转，不依赖播放状态） |
| 内存格子 | 哈希分配，随时间呼吸 |
| 时空网格 | 每个顶点按到奇点的距离下垂 |
| 心电图 | P-QRS-T 四段高斯叠加，相位跟拍点锁定 |

### 故障是合成的，不是滤镜

整帧先画在离屏画布上，再分段拷到可见画布：

```js
for (i = 0; i < bands; i++) {
  drawImage(sc, 0, y, W, h, shakeX + jump, y + shakeY, W, h);
}
```

`jump` 来自哈希噪声，`bands` 来自故障强度，强度来自：底鼓冲激 + 军鼓 + 镲 + 段落切换 + 场景本身。
红色段落再叠一层 `difference` 反相。文字和图元的色散是**画三遍**：红左、青右、白中。

### 性能

背景（底色 + 两套条纹 + 顶部辉光 + 暗角）一次性烘焙成位图，之后每帧一次 `drawImage`。
这一步把全片平均帧时间从 13.4ms 降到 **6.2ms**（1600×900，无 GPU 的 headless 环境）。
最重的镜头（记忆风暴、记忆卡片、溢出）约 19ms，在真实 GPU 加速的浏览器里约 3–6ms。

## 7. 和参考项目的关系

这个项目以同目录的 `KOKORO_ASCII_MV` 为底，但**画面是重写的**：

**沿用**
- `js/song.js`：39 句歌词的逐字时间、140.00 BPM 的节拍网格、434 底鼓 / 282 军鼓 / 45 镲、
  2,828 点 RMS 包络。这套时间轴是从 MIDI 与逐字卡拉 OK 表对齐出来的，很准，没必要重做。
- 播放器的骨架：`audio.currentTime` 作为唯一时间基准、纯函数式 `drawFrame(t)`、
  `SYNC` / `LYRIC` 两个偏移、localStorage 记忆、键盘操作。

**重做**
- 渲染从「ASCII 字符网格」换成「任意矢量 + 真 3D 投影 + 真排版」。
- 音源从 36MB 的 FLAC 换成 11MB 的 MP3（并剥掉了 1.2MB 的 ID3 封面）。
- 配色从「磷光绿终端」换成「深灰 + 白 + 语法高亮」的操作系统界面。
- 分镜从 45 个 ASCII 场景换成 49 个跨媒介镜头（代码、公式、3D、可视化、界面、光学故障）。

**为什么换掉 ASCII**
参考项目的约束是「全片只用字符」。这一版想验证的是相反的方向：
**在同一个时间基准下，把排版、3D、公式、界面混在一起会不会散**。
答案是只要底层仍是「一切由 t 算出」，混合媒介反而更容易卡在拍上。

## 10. 三个坑

**歌词时长不等于句子时长。**
`SONG.lines[i].d` 是「到下一句开始」的间隔，所以第 14 句（`これが私の望んだ「ココロ」？`）
的 `d` 是 20.9 秒——它把后面 16 秒的间奏也算了进去。
直接用它做淡出，字幕会在空乐段里整整挂 20 秒。
现在改用**最后一个字的结束时间**做句尾，多留 0.55 秒淡出。

**「字幕」不等于「歌词」。**
最开始我按歌词的方式去排这段英文——逐字高亮、贴着画面底部。
但逐字高亮会让人以为它在被唱，而它明明是旁白。
改成整行淡入、加一条细线和一个 `01 / 08` 编号之后，它才真的像字幕。

**烘焙字体时忘了基线。**
把公式画进离屏画布时，排版器给的 `y` 是相对基线的，直接拿去 `fillText` 会让所有升部被裁掉——
只有分数线和小写字母的下半截留在画面里，看起来像「公式缺了左半边」。
现在偏移量统一加一个 `ascent`。

**Canvas 的 `letterSpacing` 不进 `measureText`。**
用带字距的字体去量宽度、再用量出来的宽度做下一段的起点，两段字就会叠在一起。
所有需要「量完再画」的地方（HUD 品牌、公式右对齐）都改成先归零字距再量，手动补 `字距 × 字数`。
